(2)
I did encounter a data race with my 'count' variable. I ended up avoiding this issue by creating a count variable in the struct, and keeping those values seperate for each thread. I did not combine them into a total count until after both threads were jopined and I was ready to return the final value. I implemented this strategy in both the count and instance functions, but the instance function really gave me a hard time. I was first trying to reuse the 'count' variable I got as the return value from the count function, but kept running into bugs. I ended up creating another variable 'total' and re-calculated the count by adding together the two threads' counts based on the instance run. I was passing the count variable to both my threads, and I believe somewhere the count variable was being over written and was no longer reliable. I found that it was easiest to use local variables as much as possible, becasue it made it easier to debug and see where I was encountering errors.
